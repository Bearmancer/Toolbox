IMPORTANT DECISIONS
-------------------
- CLI stays thin: Railway propagation terminates at CLI via .Match() — CLI is a pure terminal with zero business logic.
- SyncCounters is a mutable class (not immutable record) because it is a sequential loop accumulator; mutation in-place is simpler and faster than `with` copies.
- Concrete List/Dictionary in method signatures, not IReadOnlyList/IReadOnlyDictionary — no interface abstraction ceremony.
- Build is expected to fail until Batch 4 completes due to ErrorOr type changes.
- No explicit test files (per AGENTS.md rule 4: no test NuGet packages). Verification is dotnet build + manual CLI invocation.
- No code comments (per AGENTS.md rule 9). No pragma warning suppression (per AGENTS.md rule 6).
- PowerUsage: PowerShell single quotes for raw strings to prevent variable expansion.
- Error class pattern: Errors.[Service] static classes with ApiError(string message) factories.
- Standard Railway pattern for Batch 2: ValidateInput -> CallApi -> FormatResult. Telemetry wraps the chain in using var _ = Telemetry.ForService(...).
- Standard CLI .Match() pattern: return await service.MethodAsync(args, ct).Match(success => { Console.WriteLine(success); return 0; }, error => { Console.Error.WriteLine(error.Description); return 1; }).
